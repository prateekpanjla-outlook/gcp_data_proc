## 1. Overview

`main.tf` (Layer 03: Operational) deploys the runtime resources for Phase 4: a Cloud Logging sink that exports pipeline logs to BigQuery, the Docker image build via Cloud Build, and the Cloud Run service that serves the monitoring dashboard. It also grants public (unauthenticated) access to the dashboard.

## 2. Prerequisites

- **Layer 01 (Static)** must be applied -- the `pipeline_logs` dataset and dashboard SA must exist.
- **Layer 02 (First-time)** must be applied -- IAM permissions must be granted before the Cloud Run service can query BigQuery.
- **Terraform variables**:
  - `var.project_id`, `var.region`, `var.environment` -- standard project config.
  - `var.pipeline_logs_dataset_id` -- target dataset for the log sink (from Layer 01).
  - `var.dashboard_sa_email` -- SA for the Cloud Run service (from Layer 01).
  - `var.deployer_sa_key_path` -- path to a JSON key file for authenticating `gcloud builds submit`.
  - `var.artifact_registry_repo` -- AR repository name (created in Phase 1).
- **Phase 1** must be deployed -- provides the Artifact Registry repo and Cloud Build SA.
- **Source code** at `src/github_archive/phase4_monitoring/` must be present (Dockerfile, app.py, requirements.txt, queries/, templates/).

## 3. Upstream & Downstream Dependencies

**Upstream (what must exist before this layer)**:
- `01_static/main.tf` -- dashboard SA and pipeline_logs dataset.
- `02_first_time/main.tf` -- IAM permissions for the dashboard SA.
- Phase 1 Terraform -- Artifact Registry repo and Cloud Build SA.
- Phase 1-3 Cloud Run/Function services -- the log sink filter targets their log output.
- `src/github_archive/phase4_monitoring/` -- application source code.

**Downstream (what depends on this layer)**:
- The log sink auto-creates tables in the `pipeline_logs` dataset (e.g., `run_googleapis_com_stderr`, `run_googleapis_com_stdout`), which the dashboard queries read.
- The Cloud Run service URL is the user-facing dashboard endpoint.

## 4. IAM & Service Accounts

- **Cloud Build SA:** `{env}-cloud-build` (from Phase 1) — used by `gcloud builds submit` to build and push the Docker image to Artifact Registry. Specified via `--service-account` flag in the `null_resource.build_dashboard_image`.
- **Cloud Run runtime SA:** `{env}-pipeline-dashboard` (from Layer 01) — the Cloud Run service runs as this SA, using the IAM permissions granted in Layer 02 to query BigQuery.
- **Log sink writer identity:** Auto-generated by GCP when the log sink is created. Granted `roles/bigquery.dataEditor` on the `pipeline_logs` dataset so it can write exported log entries.
- **Public access:** `allUsers` is granted `roles/run.invoker` on the Cloud Run service, making the dashboard publicly accessible without authentication.
- **Cross-reference:** `learnings/phase4_deployment_issues.md`:
  - Issue 4 — the deployer SA (used by `gcloud builds submit` via `GOOGLE_APPLICATION_CREDENTIALS`) needed `roles/logging.admin` to create the log sink.
  - Issue 15 — stale SA cleanup (handled in Layer 02) must complete before this layer can deploy cleanly after a destroy/recreate cycle.

## 5. Code Walkthrough

1. **`google_logging_project_sink.pipeline_logs` (lines 6-21)**: Creates a project-level log sink exporting to the `pipeline_logs` BigQuery dataset. The filter captures logs from `cloud_run_job`, `cloud_run_revision`, and `cloud_function` resource types where the service/job name matches `github-archive`. Uses partitioned tables (`use_partitioned_tables = true`) for cost-efficient time-range queries.

2. **`google_bigquery_dataset_iam_member.log_sink_auto_writer` (lines 24-29)**: Grants the log sink's auto-generated writer identity `roles/bigquery.dataEditor` on the pipeline_logs dataset. The `writer_identity` is a GCP-managed service account automatically created for the sink.

3. **`null_resource.build_dashboard_image` (lines 32-51)**: Triggers a Cloud Build when source files change (tracked via `filesha256` of Dockerfile, requirements.txt, and app.py). Runs `gcloud builds submit` to build and push the Docker image to Artifact Registry. Authenticates with a deployer SA key file and uses the shared Cloud Build SA (`{env}-cloud-build`).

4. **`google_cloud_run_v2_service.dashboard` (lines 54-89)**: Deploys the Flask dashboard as a Cloud Run service. Key configuration:
   - Depends on the image build completing first.
   - Sets `PROJECT_ID` and `DATASET_ID` environment variables for `app.py`.
   - Resource limits: 1 CPU, 512Mi memory.
   - Scaling: 0 to 1 instances (scales to zero when idle).
   - Runs as the dashboard SA.

5. **`google_cloud_run_v2_service_iam_member.dashboard_public` (lines 93-99)**: Grants `roles/run.invoker` to `allUsers`, making the dashboard publicly accessible without authentication. A comment notes this can be replaced with IAP or IAM-gated access if needed.
